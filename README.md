Welcome to the lego-spike-simulator project. The aim is to provide
an environment where LEGO spike robots can be simulated and the
code tested before uploading to a real LEGO spike robot.

The environment currently only supports the blockly based programming
language.

The simulator allows lego format llsp3 programs to be loaded and saved,
and can load robots in the ldraw format (ldr and mpd extensions).
Port connectivity can be specified, and saved into a robot to be loaded
again at a later time. A basic scene can be setup using images for a base
map and ldraw objects for obstacles in the scene.

There is very limited physics at the moment, focussed on moving a
wheel base with a specific gearing.

The system is currently available at http://spike.ahardy.za.net/.
However, the system can be built locally and executed directly
from files, so no webserver is required. The software can run completely
from the web browser.

# Self-hosting with a shared library

This fork adds a small server (`server/server.mjs`) and a Docker image that:

-   serves the simulator,
-   downloads the LDraw parts library once and serves it, so robots and scenes
    load their bricks without visitors uploading `complete.zip`,
-   keeps a shared library of robots (`.mpd`) and scenes (`.spk`), with an
    optional default robot and scene that load when the simulator opens.

Everyone can open entries from the library (the database button in the
simulator toolbar). Saving, deleting and choosing defaults is allowed for:

-   clients on your LAN connecting directly, when `LAN_WRITE_PREFIXES` is set
    (for example `192.168.0.`),
-   people signed in through Cloudflare Access, when `CF_ACCESS_TEAM_DOMAIN`
    (for example `myteam.cloudflareaccess.com`) and `CF_ACCESS_AUD` (the Access
    application's audience tag) are set. Protect the path `/api/admin` with the
    Access application.

```
docker run -d -p 8093:8080 -v /path/to/data:/data \
    -e LAN_WRITE_PREFIXES=192.168.0. \
    ghcr.io/danmartinez78/lego-spike-simulator:latest
```

`/data/library` holds the library and `/data/ldraw` the parts library. Delete
`/data/ldraw` to fetch a newer parts library on the next start.

# Realism modes

The settings (cog) button has a Realism section. "Ideal" is a perfect robot,
as in the original simulator. "Realistic" and "Challenging" add start
position errors, wheel size mismatch, wheel slip, motor overshoot, gyro drift
and sensor noise, so programs that only count rotations drift while programs
that check sensors stay on target. Each value can be tuned, and a fixed seed
makes runs repeatable. A link such as `/?realism=realistic` selects a preset.

The "▶ ×5" button runs the program five times and draws every path on the
mat, with how far apart the runs ended.

# Example programs

The book button in the code panel opens example programs with lesson cards
(what it does, why it works, things to try). They live in the shared library
under `programs/` as `.llsp3` files with a `<name>.llsp3.json` lesson card, and
signed-in coaches can save the current program as a new example.

The bundled examples and practice scenes are generated by
`tools/examples/make_examples.py` and `tools/examples/make_scenes.py`. They are
written for Driving Base 3 (drive motors C and D, colour sensor B).
